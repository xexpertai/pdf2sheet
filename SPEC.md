# pdf2sheet: SPEC

## 1. Purpose
Freelance "PDF to Excel" and data-entry jobs are often done by hand by retyping tables. pdf2sheet does this in the browser. It extracts tabular data from **text-based** PDFs (not scanned images), lets the user correct the column layout and cells, and exports a clean XLSX or CSV. Nothing is uploaded anywhere: the whole app is static files and works offline.

Author: Harsha Shinde. AI-assisted development is disclosed in the README. All sample PDFs are fictional demo data generated by a script in the repo and labelled "DEMO DATA".

## 2. Scope
In scope: text-layer PDFs, single or multi-page, with one or more tables per page. Out of scope: OCR of scanned PDFs, password-protected PDFs, and a server backend. If a PDF has no text layer, the app detects this and shows a clear message.

## 3. Tech constraints
- Plain HTML5, CSS and vanilla JavaScript (ES modules). No framework and no build step needed to run: open `index.html` through any static server, or use GitHub Pages.
- Vendored `pdfjs-dist` (Apache-2.0) in `vendor/`, with its licence file included. The XLSX writer is **written by us** (`src/xlsx.js`, a minimal OOXML and store-only ZIP writer with CRC32), so there is no SheetJS dependency.
- Core logic (`src/extract.js`, `src/xlsx.js`, `src/csv.js`) consists of pure functions that also run in Node 20+ for tests (`node --test`).
- Total app payload excluding pdf.js is 150 KB or less.

## 4. Features and acceptance criteria

### F1. Load PDF
- Drag-and-drop or a file picker accepts `.pdf` files up to 20 MB. Larger files, or files that are not PDFs, show an inline error and the app does not crash.
- AC1: Loading `samples/invoice-demo.pdf` shows a page thumbnail strip and the page count within 3 s on a mid-range laptop.
- AC2: Loading `samples/scanned-demo.pdf` (image only) shows "No text layer found: this PDF looks scanned; OCR is not supported."

### F2. Automatic table detection (`extract.js`)
- Groups text items into rows by y-coordinate (tolerance = 0.5 × median glyph height) and into columns by clustering x-start positions across rows (gap threshold configurable, default 8 pt).
- Merges multi-line cells when a row has text only in non-first columns and lies directly under a full row (wrapped description).
- Detects a header row as the first row whose cells are all non-numeric and at least 2 columns wide.
- AC3: For `samples/price-list-demo.pdf` (3 pages, 5 columns, 120 data rows, header repeated on each page), extraction yields exactly 120 data rows and 5 columns, with the repeated headers removed.
- AC4: For `samples/statement-demo.pdf`, wrapped descriptions are merged into one cell, and the extracted rows equal `samples/expected/statement-demo.csv` cell for cell.
- AC5: Numbers such as `1,234.50`, `(45.00)` and `-12` are parsed to numbers (1234.5, -45, -12). Currency symbols are stripped into a separate option "keep as text". Dates in `DD/MM/YYYY` and `YYYY-MM-DD` are recognised.

### F3. Review and fix UI
- The page preview (canvas) shows detected column boundaries as draggable vertical lines. The user can add a boundary (click), remove one (double-click), and limit the extraction to a page range and a y-region (drag a box).
- A results grid is editable (contenteditable cells). The user can rename headers, delete rows or columns, and mark a row as a header.
- Re-extraction after a boundary change completes in under 300 ms for a 120-row page set.
- AC6: Dragging a boundary on `price-list-demo.pdf` so that two columns merge updates the grid to 4 columns immediately.
- AC7: The grid is keyboard-navigable (arrow keys, Enter to edit, Esc to cancel). Controls have labels, and axe-core reports 0 serious or critical violations.

### F4. Data checks
- A side panel shows the row count, the empty-cell count per column, the inferred type per column (number, date or text), and rows whose numeric column fails to parse (highlighted in the grid).
- An optional "Totals check" lets the user pick a numeric column and a total value typed by the user, and shows match or mismatch with the difference.
- AC8: For `invoice-demo.pdf`, the sum of the Amount column equals the invoice's printed subtotal (a test asserts this).

### F5. Export
- XLSX: one sheet per table, a bold header row, typed numeric and date cells (not strings), auto column widths, and a frozen top row.
- CSV: UTF-8 with BOM (option), choice of delimiter (`,` `;` or tab), and RFC 4180 quoting.
- A "Copy as TSV" button pastes straight into Excel or Google Sheets.
- AC9: The exported XLSX opens without a repair prompt in Excel and LibreOffice. The Node test unzips it, validates `[Content_Types].xml`, `workbook.xml` and `sheet1.xml`, and checks that numeric cells use `t="n"`.
- AC10: A CSV round trip of cells containing commas, quotes and newlines re-parses to identical values.

### F6. Presets
- Column boundaries, header settings and the region can be saved as a named preset in localStorage, and exported or imported as JSON. This lets the same monthly statement layout be reused with one click.
- AC11: Applying a saved preset to `statement-demo.pdf` reproduces the AC4 output without any manual step.

## 6. Quality gates
- `node --test` passes all tests: AC3–AC5 and AC8–AC11 are automated against the fixture PDFs using the pdfjs-dist legacy build.
- A Playwright smoke test (optional script) loads a sample, exports the XLSX, and checks the downloaded file is non-empty.
- No network requests at runtime (verified in the DevTools/Playwright request log). There are no analytics.
- Responsive from 360 px wide upward, and works in current Chrome, Firefox and Safari.
- README: a one-paragraph pitch, a GIF or screenshot, "How it works" (row and column clustering explained), limitations (no OCR), a privacy statement, an AI-assistance disclosure, and the author Harsha Shinde.

## 7. Definition of done
All of AC1–AC11 pass, the repo is deployed to GitHub Pages with a live demo link in the README, the sample PDFs are labelled DEMO DATA, and no secrets or external services are used.
